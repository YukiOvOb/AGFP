# UC03 设备领用和归还

核心参与者为 Custodian；Borrower 是预约申请人及实际借用人。领用和归还均在现场发生，登录用户只记录已经实际发生的交接。系统为库管提供已确认预约队列和活动借用列表，为借用人提供自己的借用历史。

## 领用正常流程

1. Custodian 登录并打开 Loans and returns。
2. 系统列出未结束的 CONFIRMED 预约。
3. 库管选择记录，核对现场身份与预约中的 borrowerId，确认身份复选框。
4. 系统在设备锁内核对有效角色、预约版本、时间窗和设备事实。
5. 同一事务创建 ACTIVE Loan，保存 checkoutBy、checkedOutAt、dueAt，将预约改为 FULFILLED、设备改为 ON_LOAN，记录成功审计并发布 LoanEvent。
6. 提交成功后刷新列表并显示结果。

## 领用异常流程

未登录返回 401，无交接角色或停用账号返回 403。未确认身份或版本参数非法返回 400。预约不存在返回 404。未审批、取消、拒绝、已经领用、时间未到或已经结束、借用人不匹配或停用、设备故障或已有活动借用均拒绝交接。版本已变化返回 409，页面刷新并要求重新选择。并发领用相同预约只有一笔成功，失败交易不产生 Loan 或成功审计。

## 归还正常与异常流程

库管找到 ACTIVE Loan，选择 Receive return，核对设备并填写 GOOD 或 DAMAGED。系统以版本和行锁验证借用，记录 RETURNED、returnBy、returnedAt、condition 和 note。损坏必须描述，自动生成关联维修单及维修历史。归还时间晚于到期时间时同时保留迟还事实；不建立 OVERDUE Loan 状态，也不自动收取罚款。

早归还不释放原预约时间段。仍有活动维修时设备保持 UNDER_MAINTENANCE；设备已经 RETIRED 时允许接收实物，保持 RETIRED；正常且无活动维修/借用时恢复 AVAILABLE。重复归还或旧版本返回 409；归还时间早于领用时间拒绝。维修单、审计或同步事件消费者失败会回滚整笔交易，不留下部分归还。

## 设计问题与模式选择

问题是领用允许状态和归还后的目标状态容易散落在 Controller、Service 和维护模块中。直接方案是每个动作写 if/else 检查 AVAILABLE、ON_LOAN、UNDER_MAINTENANCE、RETIRED；简单但容易在新增操作时遗漏报废优先级。

候选包括直接条件判断、完整类层次 State Pattern、enum 状态对象。当前使用 `EquipmentLoanState` 的 enum singleton 状态对象：AVAILABLE 覆写 `permitsCheckout()`，其他状态拒绝领用；`afterReturn()` 集中实现报废、维修、持有的优先级。Service 负责事实查询、角色和时间窗、锁与事务，状态对象不访问数据库。Loan 只有 ACTIVE/RETURNED，保持简单业务检查，不制造 OverdueState。

模式前，Service 每个操作自行比较字符串并决定是否交接。模式后，Service 将设备状态相关操作委托给状态对象，测试能独立枚举所有状态及优先级。取舍是 enum 仍集中定义有限状态，新增状态需要修改该类型；当状态专属行为增多时再拆分独立类。维修业务原有状态机不被 UC03 替换，只通过其公开 Service 建立故障记录。

## 验收条件

| 场景 | 预期结果 |
| --- | --- |
| 合法领用与正常归还 | 四类事实和审计一致，版本递增 |
| 未审批、取消、提前、到期边界、故障 | 领用被拒绝且没有部分写入 |
| 借用人不匹配、停用账号、撤销库管角色 | 拒绝交接 |
| 并发领用 / 并发归还 | 仅一次成功，无重复借用或维修单 |
| 逾期且损坏 | RETURNED + 迟还事实 + DAMAGED + OPEN 维修单 |
| 已报废或仍在维修 | 接收归还，不恢复 AVAILABLE |
| 同步消费者失败 | 借用、设备、维修和审计一起回滚 |
| 借用人访问他人记录 | 列表不泄露，详情 404，无写权限 |
| 版本冲突页面 | 提示错误、刷新并重新选择，不显示成功 |
